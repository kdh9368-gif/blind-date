# 블라인드 소개팅 채팅 · 설치 안내

한 번에 한 커플, 10분 채팅, 공동 랜덤 질문, 운영진 강제 종료와 초기화를 지원합니다. 참가자 개인정보를 수집하지 않습니다.

## 1. Firebase 준비

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 프로젝트를 만들고 **Authentication → Sign-in method → 이메일/비밀번호**를 켭니다.
2. **Authentication → Users**에서 계정 세 개(A, B, 운영진)를 직접 만듭니다. 각 계정의 **UID**를 복사합니다. 참가자에게는 운영진 계정을 알려주지 마세요.
3. **Realtime Database**를 만들고 잠금 모드로 시작합니다. 데이터베이스 URL을 복사합니다.
4. **프로젝트 설정 → 내 앱**에서 웹 앱을 등록하고 `firebaseConfig` 값을 복사합니다.
5. `firebase-config.js`의 웹 앱 설정값과 세 UID는 이미 입력되어 있습니다. **비밀번호는 코드에 넣지 마세요**.
6. `database.rules.json`의 UID도 이미 입력되어 있습니다. Realtime Database → **규칙**에 JSON 전체를 붙여 넣고 **게시**합니다. 이 보안 규칙을 게시해야 참가자 계정에서 관리자 동작을 할 수 없습니다.
7. Authentication → Settings → Authorized domains에 배포한 GitHub Pages 도메인을 등록합니다(필요한 경우).

## 2. GitHub Pages 배포

이 폴더 **안의 파일 전부**를 새 GitHub 저장소의 최상위에 업로드합니다. 저장소 Settings → Pages → Deploy from a branch → `main` / `(root)`를 선택합니다. 이후 제공되는 주소에서 `admin.html`, `participant-a.html`, `participant-b.html`을 각각 엽니다. `index.html`만 업로드하면 채팅은 작동하지 않습니다.

## 3. 현장 운영

1. 운영진은 `admin.html`, 참가자 두 노트북은 각각 A/B 페이지에서 자기 계정으로 로그인합니다.
2. 첫 회차 전에 운영진이 **다음 커플 준비**를 눌러 세션을 만듭니다. A/B 화면의 접속 상태를 확인하고 **소개팅 시작**을 누릅니다.
3. 참가자는 10분 동안 대화하며 랜덤 질문을 함께 볼 수 있습니다. 시간이 끝나면 화면에서 전송이 잠깁니다. 운영진이 필요하면 강제 종료할 수 있습니다.
4. 커플이 자리를 떠난 뒤 **다음 커플 준비**를 누릅니다. 이전 대화와 질문이 DB에서 삭제됩니다. A/B 화면을 새로고침해 새 세션에 접속한 상태를 확인합니다.

## 유의사항

- 기존 커플이 노트북에 남아 있다면 새 세션에 참여할 수 있으므로, 초기화 전에 반드시 자리를 비우게 하고 노트북은 운영진이 관리하세요.
- 참가자 계정은 노트북에 저장될 수 있습니다. 축제 후 세 계정을 삭제하거나 비밀번호를 변경하세요.
- 네트워크가 끊기면 메시지가 전송되지 않습니다. 재연결 후 상태를 확인하세요. Firebase의 서버 시각으로 메시지 전송 기한을 검사합니다.
- 질문 기록을 포함한 세션은 초기화 시 삭제됩니다. 클라우드 백업이나 스크린샷까지 삭제하는 기능은 포함하지 않습니다.
